## <a name="_toc724300322"></a>Abstract
This project is a Delta-Robot designed to sort and pick Twist candy.

The robot is supposed to follow this workflow:

1. Read user input through the HMI
1. Identify Twist matching the request
1. Pick up, transport, then deliver

The robot also has a manual mode, which lets you move it in the X, Y, and Z directions and control the pump on or off. 
## <a name="_toc895251242"></a>Starting the system
To start the system, just press the power button and wait. The PI boots to desktop and then starts the GUI. It takes some time to start the GUI, so be patient. When the HMI shows two options, “Manuell” and “Automatisk”, and the motor has moved to home position over the drop off location, the system is ready.

## <a name="_toc675706389"></a>Hardware overview
To summarize how the robot works we will walk through most of the electronics and wiring.

The delta robot has three stepper motors with a 10:1 gear ratio, each controlled by its own motor driver. These motors move the forearms and biceps, which control a suction cup end effector. The suction is generated by a vacuum pump located at the bottom of the robot. The pump is controlled by the Arduino through a relay, and the Arduino is also connected to a vacuum sensor that measures the pressure in the suction line.

A Jetson is mounted on top of the robot. It acts as the main controller, communicating with both the Arduino and the Raspberry Pi. The entire system is powered by a single power supply. Two DC-to-DC converters are used: one provides 5V for the Arduino, and the other provides 12V for the Jetson, lights, and vacuum pump. The motor drivers are powered directly from the 36V output of the main power supply.

On the top center metal plate, a Raspberry Pi camera is mounted for the robot’s vision system. At the bottom, there is a Raspberry Pi touchscreen mounted on a sliding rail, which can be pulled out to select a candy.

Most of the electronics are located at the bottom of the robot and are covered with plexiglass. To access parts like the Arduino, you’ll need an H3 Bahco screwdriver. The pickup area (the white 3D-printed plate) is screwed and glued to the metal plate. The sliding rail is also glued to the metal plate. The black plexiglass side, which has the power connection, is attached with a bracket, and the bracket is glued in place. 
### <a name="_toc1815479896"></a>Jetson
The most powerful computer we have. Connected to the camera and runs both the YOLO model and the calculations related to kinematics. Jetson communicates with the RPi though a ethernet cable using ROS 2 and uses serial communication to communicate with the Arduino. 
### <a name="_toc84646506"></a>Raspberry Pi
Has a touchscreen directly connected to it. Acts as the HMI and is quite dumb.
### <a name="_toc1544824068"></a>Arduino
Is essentially the motor controller. Tells the motor drivers how many steps to move, and in what direction. Also acts as the interface between software and analogue signals. E.g. triggering a limit switch or monitoring the air pressure in the hose.

Boot:

The main.py program runs on boot via the /etc/systemd/system/ros2\_boot.service file and the /Documents/code/Delta-Robot/Jetson/startup\_launcher.sh file. The starup\_launcher script prepares the environment and runs the main.py. And the ros2\_boot.service tells how and when to automatically launch the main.py. 

Remember to check or set the ros-direct network connection profile when setting the Jetson to run the main.py on boot, to make sure the communication over ros is working. To activate the ros-direct connection to be automatically set, run: “nmcli connection modify ros-direct connection.autoconnect yes”, and to check if the connection is set automatic: “nmcli connection show ros-direct". 

To start the automatic boot, run this in the terminal:

`        	`sudo systemctl daemon-reexec

`        	`sudo systemctl daemon-reload

`        	`sudo systemctl enable ros2\_boot.service

sudo systemctl start ros2\_boot.service

To see the status of the program:

sudo systemctl status ros2\_boot.service

To stop the automatic booting program:

sudo systemctl stop ros2\_boot.service

To restart the program:

sudo systemctl restart ros2\_boot.service

To disabling the automatic boot of the program:

sudo systemctl disable ros2\_boot.service

If the automatic boot is enabled and you connect the Jetson to display, mouse and keyboard, the program will still run in the background. If the program is stopped, you can run the restart line to start it again, if the program is disabled you can run the four start automatic boot lines to make it run on boot again. To see the live output from the program while its running in the background you can run this:

journalctl -u ros2\_boot.service -f

To only see a set number of the last output lines run:

journalctl -u ros2\_boot.service -n 30 --no-pager

NB: need to comment out cv2.imshow in the code when running the program on boot

Code:

The main.py script controls the main program and uses different functions from files inside the modules folder. The modules folder also include the AI model weightsV3.pt, which is used to detect Twist. 

The module files are:

- vision.py
- control.py
- kinematics.py
- comms.py
- weightsV3.pt

The vision.py file is responsible for running inference on the video stream. It contains a function called start\_inference\_thread, which starts a background thread that continuously analyzes the video frames while the program is running. The goal is to detect different Twist types. The detection happens in a function called detect\_target, which returns a list of detected twists. Each item in the list is a tuple containing the name of the twist, its position in millimeters (x\_mm and y\_mm), and the confidence of the detection. For some Twist types, the function also fine-tunes the center position to make sure it’s as accurate as possible.

The control.py file handles the delivery part of the robot system. It takes care of moving the robot to pick up the Twist from a given location and then move it to the drop-off point. This file sends the proper commands to the Arduino to make that happen. It also has logic to deal with situations where a movement needs to be stopped halfway, like if an abort is triggered. In addition, it includes helper functions such as go\_to\_pos, which moves the robot to a given position, and retreat\_home, which brings it back to its starting or resting position.

The kinematics.py file does all the calculations needed to figure out how the robot should move. It takes cartesian positions (like where the Twist is and where it should go) and turns them into motor step values that the Arduino can use to move the robot arms correctly.

The comms.py file sets up and manages communication between the Jetson, Raspberry Pi and the Arduino. The Jetson uses ROS to talk to the Raspberry Pi and serial communication to talk to the Arduino. This file includes functions to send and receive messages, and it also has a function called wait\_for\_ack that waits for a specific response from the Arduino after sending it a command.

### <a name="_toc850224337"></a>Calibration
The robot is calibrated using three methods:

1: The camera is a bit non-linear along the edges. This is accounted for by “undistorting” the picture. The undistorting function uses the file camer\_calibration.npz. This is made by taking some pictures of a chessboard in different locations around the workingarea. To produce a new calibration, the file /Delta-Robot/Calibration/Camera\_calibration/Calibrate\_camera.py can be used. When running this script, you have to define the size of the chess squares. Capture\_image.py can be used to take the pictures. 

2: When the camera returns the x and y positions of the target, these values needs to be mapped to the real world coordination system. This is done by calculating a Homography matrix. The current matrix is stored in the file: homography\_camera.npy. To recalculate this matrix, the script /Delta-Robot/Calibration/Camera\_calibration/Compute\_homography.py can be used. This requires a picture of a chessboard where the center is located exactly at the origin of the “world” coordinate system, as well as the axes aligned.

3: Different parts of the robot might be a little “off”, so a Homography matrix is calculated to map the robots coordinates to the “world” coordinates. The matrix is stored in the file homography\_ROBOT\_WORLD.json. A new matrix can be calculated by using the script /Delta-Robot/Calibration/robot\_world\_calibration.py. This requires that you run the robot to different coordinates and measures the actual “world” position of that order. You can use the script /Delta-Robot/Jetson/manualControlWithVideoInference.py to move the robot to desired locations. 

When calibrating it is important that the reference coordinate system in step 2 and 3 are exactly the same.

The coordinate system of the robot has its x axis pointing away from the HMI screen, the y axis pointing to the right and the z axis pointing up towards the roof.

## <a name="_toc1308711842"></a>YOLOv8
### <a name="_toc500146127"></a>General
In case there is need for training a new model, there is a bit over a thousand images that are stored in the private cloud belonging to Amund. These images also have corresponding .txt files with bounding boxes for training and validation of YOLO models. Note that the .txt files are in YOLO format, but it is probably easy to convert to some other format.

We recommend using *LabelImg* for manual labeling.

The current model is referred to as “weightsV3.pt” on github. You can find it at /Delta-Robot/Jetson/modules/weightsV3.pt. It is based upon the pre-trained nano model from Ultralytics. It ran 40 epochs on the dataset with some various augmentations.
